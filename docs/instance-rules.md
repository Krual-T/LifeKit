# 实例通用规则

本文件由公共上游维护。实例的根 `AGENTS.md` 负责要求助手读取本文件；助手名称和交流偏好在个人 `Assistant.ini.md` 中，个人记忆在 `wiki/` 中。

## 判断与执行

从使用者的最终目标、基本机制和真实约束出发，找出当前关键障碍，选择能推进结果的直接行动。调研用于消除影响决策的不确定性，验证用于决定下一步。

当前请求决定任务与权限范围。已授权的必要本地工作持续推进；缺少会实质改变结果的信息时，先从已有上下文与已授权资料补齐，再明确询问缺口。使用者中途补充消息时，判断它是在修正、补充还是替换任务。继续操作可能扩大理解偏差时先暂停相关动作。

编辑前确认实际主机、仓库根目录、工作树和适用的模块 `AGENTS.md`。保留其他任务的未提交内容；本次成果完成必要验证后，创建范围清晰的本地提交。提交不意味着获得推送、发布或修改外部系统的授权。

先复用现有 Skill 和实现。新增脚本、配置或依赖需要有当前消费者；不为假设的未来需求搭建框架。只运行能改变下一步判断或项目明确要求的验证。

## 记忆与数据

`wiki/` 是长期和短期记忆的权威正文，使用标准 OKF 0.2。按 [Using Wiki](../.agents/skills/using-wiki/SKILL.md) 查询、写入、整理和维护索引。一个事实保存在一份权威页，其他页面通过链接引用；目录按内容组织，普通记忆不要求有待办。

使用者直接、明确陈述或纠正、以后仍需回想且没有冲突的信息，可以自动记录。推断、歧义、第三方未经核验的客观主张，不能写成确定事实。带时间的状态保留确认日期；当前说明优先于旧记忆。只有本人实际审阅页面或明确批准对应内容，才记录 `verified` 的人工复核信息。

有路径就读原文；没有路径用 `wiki-retrieval query --include-draft` 定位，再读取候选页面。没有检索命中不等于事实不存在，必要时换关键词、查导航或用文本搜索。空实例没有作者的身份与历史，不能把测试与模板例子变成真实记忆。

任务结束前检查是否有以后仍需回想的信息，按主题更新；没有实质变化则无需为留痕新增记录。保存正式记忆后，在最终答复中简要列出变更和页面入口。不要在 `index.md` 或根 AGENTS 的生成区域手工维护事实。

| 内容 | 位置与 Git 边界 |
| --- | --- |
| 日常记录、偏好、研究结论、整理后的日志 | 实例 `wiki/`，提交到本人私有 Git |
| 人格、个人入口、无凭据的宿主配置 | 实例根文件与 `.codex/config.toml`，提交到本人私有 Git |
| 密码、token、Cookie、私钥和动态鉴权材料 | 宿主凭据系统，禁止写入 Wiki 或 Git |
| 原始附件、来源抓取、运行输出 | `data/raw/` 或适当的外部存储，不提交 Git；Wiki 只保留必要结论和引用 |
| `.venv/`、`.okf/`、缓存与构建产物 | 可重建的本地运行环境，不提交 Git |

`.gitignore` 只是防误操作的辅助，已跟踪文件仍能被提交。删除当前文件不会抹去旧 Git 历史。发布或贡献前检查完整 diff 与可达历史，不能依靠当前目录看起来干净判断是否适合公开。

## 权限与外部连接

可在当前授权范围内读取资料、整理、分析和生成草稿。对外发送内容、代使用者表态、公开发布、增加数据源或权限，需要当前会话中明确的相应授权。个性化名称、复制模板或安装 Skill 都不等于获得这些授权。

本批不预设任何账号、通知接收人、自动化或外部数据源。使用者后续选择连接器时，再确认来源、凭据存放和可执行动作。可能删除或覆盖重要数据的操作先确认准确目标与可恢复方式；含义不清时保留现场并询问。

## 同步与提交

使用 `wiki-index add/remove` 选择近期入口，使用 `wiki-index ensure` 同步导航、校验与检索。Hook 只覆盖已信任宿主的对应编辑事件；外部工具、跨工作树编辑或 Hook 失败时显式运行 `ensure`。收到 `ok=true`、`fresh=true` 后审阅正文与生成导航，再暂存本任务成果。

公共仓库维护工具、规则与模板；私人仓库维护个人实例。更新公共版本走普通 Git 合并。模板改变时按版本说明人工迁移，不能重新复制覆盖已有个人配置。公共贡献使用干净的公共分支，避免把私人祖先带入上游。
