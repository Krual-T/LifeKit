# 现有私人实例首次接入

已有私人历史的仓库，可以保留历史并一次性合并独立的公共 T0。先在隔离工作树验证；公共候选和私人实例应始终使用不同目录与远程。

1. 确认公共 T0 是不含私人祖先的独立根提交；不要把旧私人仓库的可见性直接改为公开。
2. 记录私人起点 P0，保留一个明确的本地分支作为恢复引用。完成本任务修改的提交，保留其他任务的工作区。
3. 在干净的接入工作树添加公共 `upstream`，获取并选择经过审阅的 T0 提交。第一次执行 `git merge --no-commit --no-ff --allow-unrelated-histories <T0>`。后续版本有共同祖先，不再需要这个选项。
4. 逐文件解决共享路径的 add/add 冲突：公共工具采用已验收版本；私人 Wiki、人格、实际 AGENTS、启用配置和未提取模块保留。保留 AGENTS 中的个人入口、近期 marker 与个性化约定，将其中跨实例通用的规则改为对 `docs/instance-rules.md` 的明确读取要求，例如“开始任务时先读取并遵守 `docs/instance-rules.md`；本文件另行声明的实例约定作为补充”。避免保留一份会与上游规则独立演进的通用规则副本。忽略规则合并双方真实数据边界。不要用 `-s ours` 或整树覆盖假装完成接入。
5. 新的模板不替换已有文件。当前人格若由其他宿主路径加载，可暂时保留，此时不要再加载 `Assistant.ini.md`。切换到人格模板时明确更新根 AGENTS 的读取路径，并移除旧的加载入口。确认始终只有一份当前人格来源。
6. 在该工作树的独立环境运行记忆、索引和受影响能力测试；比对 P0 下的私人文件与个人配置。验证通过后提交双父合并 M0，确认 P0 与 T0 都是 M0 的祖先，再按项目约定合入私人开发分支。

未提交的合并可在这个干净工作树里用 `git merge --abort` 退出；已提交的接入保留历史，通过后续修订处理问题。不要重写或删除旧私人历史。

首次接入完成后，个人日常提交和公共更新可以交替存在：

```text
公共：          T0 ───── T1 ───── T2
                ╲       ╲        ╲
私人：P0 ─────── M0 ─ P1 ─ M1 ─ P2 ─ M2
```

公共分支永远不合入私人分支。需要贡献某项通用改进时，在公共历史的新分支中单独制作并审阅补丁。
