# 从经历形成判断与改进

按实例 AGENTS 确定复盘目标和行动要求。本页用于分析性复盘；日常回忆中的感受与体验按本人原意保留。

## 先恢复事实和变化

用相关 Wiki、决策记录和既有复盘恢复当时的目标、预期、实际结果与关键选择。选择能回答本次问题的此前状态作比较，说明哪些能力、判断标准、行为、关系或精力状态发生变化。报告数量、任务数量或材料多少本身不解释变化。

同时找出此前对同一主题的判断、已采纳改进和验证约定。本次新经历是检验这些判断的机会；没有后续证据时保留待验证状态，不把旧建议写成已经实施。

## 形成解释，再决定是否提问

将重要变化连接到可观察证据和可能机制，区分直接触发、持续原因及系统条件。结合当时可得信息和可选方案评价决策；结果中的外部条件与运气单独说明。对因果尚不清楚的情况，指出最需要区分的其他解释，以及什么证据会使当前判断改变。

先利用已授权资料解决事实缺口。提问围绕资料无法恢复、且不同回答确实会改变解释或行动的一个焦点。向本人说明已有判断、依据及关键未知，让本人可以补充、反驳或修正。不让本人重新提供已经说过的背景，不把泛泛评价或逐条确认当作分析。

解释不能先替本人指定情绪、动机或人格。出现冲突时保留各方陈述及时间，明确区分事实与助手判断。跨期引用分析时沿用原有归因和不确定性。

## 将收获带到实践中

按实例要求聚焦少量保留、停止或新增的做法，将它们与原因联系起来。区分助手建议、本人决定和已经发生的行为。已采纳改进写清负责人、时机与可观察的验证方式；有适用条件的经验记录其条件，后续出现反例时修正。

学习可以涉及方法、能力、协作边界和心态：例如需要标准化的有效做法、需要补齐的信息、需要提前识别的风险、需要调整的目标或判断前提。由证据决定需要改变哪一处，不把所有原因都归结为个人更努力或更小心。

可复用的方法、决策理由和案例更新到现有主题 Wiki，复盘页链接该处。同一事实保留一份权威记录；不为每次复盘新增一套清单、模板或 SOP。下一次相关复盘检查改进的实际效果，并更新原判断。

## 回看尺度与呈现

| 尺度 | 分析重点 |
| --- | --- |
| 日 | 具体经历、当时选择、预期与结果，以及与此前不同之处 |
| 周 | 多次经历之间的联系、反复出现的机制、上次改进的效果 |
| 月 | 能力与工作方式的变化、资源与优先级取舍、已形成的方法 |
| 年 | 长期轨迹、关键转折、判断前提和协作关系的演变 |

正文按真正值得理解的主题组织。先说明时间与材料范围，再把事实、解释、未知和改进连接起来，来源紧邻相关事实。实例的多层收获是质量标准，不要求每个主题机械填满相同栏目。

完成前判断：读者是否能看清发生了什么变化、为何形成当前解释、哪些因素可控，以及下一次如何行动和验证。若只有事件复述或通用道理，继续回到材料分析；证据不足则明确具体缺口，不用更多问题或更长篇幅代替结论。
