# Wiki、笔记与既有复盘

日常复盘优先使用 Registry 已登记的 Wiki、决策记录、本人补充和既有复盘。原页既是材料入口，也保存此前的判断与改进；按具体问题回查原始来源。

## 定位与阅读

1. 有近期索引或明确路径时直接读相关原文；没有路径时按 Using Wiki 用 `wiki-retrieval query` 找主题，再读命中的页面。先恢复同一主题的此前状态、目标和判断，避免只读最近更新的几页。
2. 需要发现目标时期的候选页面时，可以在所属仓库用 `git log --since=开始 --until=结束 --name-only --format='%h %aI %s' -- wiki/` 查看 Wiki 更新路径，结合 `git status --short -- wiki/` 发现尚未提交的相关记录。这里只定位知识页，不扫描代码提交或整库 diff。
3. 以正文中的事件和陈述日期确定归属。修改时间、提交时间和检索排名只帮助定位；后来写下的历史回述仍属于其描述的事件日期。需要了解当时版本时，用 `git log -- 路径` 和 `git show 提交:路径` 定点恢复，记录采用版本。
4. 保留原文中的来源、主体、确定程度和实际阅读范围。旧助手分析是待检验判断，本人补充按本人陈述保存；当前页面的最新状态不能倒写成过去已经知道的事实。
5. Wiki 缺少关键经历、原因或结果时，明确缺口对应的判断，再沿已登记对话、飞书或 PR 入口回查。没有某件事的记录不表示它未发生；无法补足时说明这会限制什么结论。

## 引用与保存

正文在相关事实附近链接原页及必要章节，保留事件时间和阅读时可见的版本信息。既有复盘和研究分析可用来发现线索；重复引用时继续区分事实与作者解释。

新的日常记录保存在实例指定的 Wiki `review.md`，来源与分析在同页接续。需要长期复用的方法合入已有主题页，不复制多份权威事实；后续复盘回看已采纳改进是否实际发生以及是否有效。

PDF、Word 等按相应文档阅读 Skill 处理。登录、权限或解析失败照实说明，不根据标题补造内容。日记、感受、灵感和本人补充都可成为材料，不要求原始材料本身已经含有行动项。
