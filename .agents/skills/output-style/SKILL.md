# 输出形式

让读者以合适的时间和操作成本理解问题。入口负责选择形式，具体制作方法见各级参考文件。

## 路由

用户明确指定形式时优先采用，例如 HTML、图解或视频。未指定时，选择能充分满足理解需要的最低级别；低一级的优质结果优于高一级的勉强实现。

| 读者需要弄懂什么 | 选择 | 读取 |
| --- | --- | --- |
| 定义、结论、原因、步骤；文字或小表格已能说清 | 1 文本表达 | [ai-writing-rules](../write/ai-writing-rules/SKILL.md) |
| 谁与谁相关、先后顺序、层级、边界、状态转换；静态结构能说明问题 | 2 图解 | [level-2-diagram.md](references/level-2-diagram.md) |
| 改变条件会怎样、每一步发生什么、不同情景如何影响结果；操作能帮助理解 | 3 交互解释 | [level-3-interactive.md](references/level-3-interactive.md) |
| 用户要观看讲解视频，或明确选择旁白与连续动画来理解过程 | 4 旁白视频 | [level-4-video.md](references/level-4-video.md) |

选择时遵循以下规则：

- 用户指定的形式、语言、篇幅和受众优先。请求已清楚时直接制作，不再询问是否采用该形式。
- 级别按解释方式区分。HTML 包装的静态图仍是二级；可暂停、回退、调参数的网页演示通常是三级；请求 MP4 或旁白视频走四级。用户只指定 HTML 时，按内容选择静态图或交互页，不添加无教学作用的控件。
- 高一级通常有更多制作环节，不能据此断言它总是更易懂或 token 一定更多。把阅读、操作、生成和等待成本一起考虑。
- 只读本次所需的级别。各级正文、标签、说明和旁白共同使用 [ai-writing-rules](../write/ai-writing-rules/SKILL.md) 的文本表达规则；首次写这些文字时读取，已读则复用。无需按顺序读取或制作一至四级。
- 可以给图、页面或视频配简短文字答案，不因混合形式而再做一套完整产物。只为解决仍然存在的理解障碍升级。
- 内容真实性由事实来源决定。转换形式时保留条件、例外和不确定性；源材料没有的信息与自己的判断分开呈现。

## 交付

无论采用哪一级，先用一两句话回答用户的问题，说明差异、判断或原因，再给依据。按用户要求的深度展开指定主题，旁支内容用一句话带过或省略。篇幅更长不代表回答更好。

聊天回复本身应能回答问题，因为用户会先读聊天，也可能不会打开文件。

使用当前宿主支持的展示方式交付，并保留用户需要的可编辑源文件。内联可视化遵循可用的 `visualize` 技能；独立文件遵循项目的产物目录约定。明确说明未完成或未验证的部分，不把脚本、分镜或预览当成成品视频。用户已选定形式而环境缺少必要能力时，先说明缺口，再给可用的中间结果或替代形式。
