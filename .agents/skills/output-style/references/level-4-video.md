# 四级：旁白视频

旁白、字幕和标签使用 [ai-writing-rules](../../write/ai-writing-rules/SKILL.md) 的文本表达规则。观众需要能听懂并跟上可见变化；不要把长文分页朗读当作机制讲解。

## 先选可执行的制作方式

先确认现有渲染器、视频合成工具与旁白能力，再制作分镜。数学、几何或 3Blue1Brown 风格优先现有 Manim；其他风格可用当前已有的视频工具或 Remotion 等引擎。只使用本环境实际可用的工具或技能。

旁白优先沿用用户已配置或指定的服务，也可用支持目标语言的本地语音合成工具。生成一小段，确认读音和节奏合适后再生成全片；只有声音选择会影响结果且现有偏好不足时才询问。调用外部配音服务须遵循当前授权范围；密钥只交给对应客户端，不能写进脚本正文、提示词或交付物。

缺少工具或旁白能力时，说明缺口，提供可编辑分镜和已有的源文件，标明尚未渲染或尚未配音。需要增加服务、安装环境或发生额外费用时，沿用当前会话权限处理。

## 分镜

1. 确定要解释的问题、受众和有用的具体例子，核对来源事实。默认简短讲解，概念确有需要时再展开。
2. 编写包含“画面变化、旁白、时长”的分镜表。从直觉入手，展开机制，再用例子检验。动画表现有意义的变化，标签保持易读，旁白保持简洁。

每个场景占一行、说明一个观点，例如：

| 场景 | 时间（秒） | 旁白原文 | 屏幕内容 | 动画 |
| --- | --- | --- | --- | --- |
| 1 | 0 至 6 | “注意力机制让每个词都能参考其他词的信息。” | 一个由 5 个词元组成的句子 | 词元从左到右淡入 |

## 旁白与画面

- 旁白对应屏幕上的内容，例如“这个箭头表示查询，它依次指向各个键”。
- 术语首次出现时解释，之后保持名称一致。
- 按句或自然语段生成语音，记录每段的实际时长，据此安排动画，让画面与提到它的旁白同步。中文不套用英文每分钟词数，以听感连贯和同步准确为准。
- 保留有意义的停顿与最终状态停留，字幕避开关键标签。背景音乐、片头片尾和字体按内容及用户要求选择。

### 数学可视化风格

题材或用户要求适合 3Blue1Brown 风格时，可采用以下方式：

- 深色背景、浅色图形与文字，用一种强调色突出解释对象，第二种强调色仅用于对比。
- 用几何表现机制：平面箭头表示向量，向量之间的对齐程度表示点积，条形长度表示权重。
- 通过移动、拆分、组合和变形逐步构建下一状态。对象变形前先淡出文字标签，避免中途出现乱码。
- 每次引入一个新对象或变化，与提到它的旁白同步。
- 新变量首次出现时，展示它从何而来，例如注意力机制中的 `q = W_Q x`、`k = W_K x`、`v = W_V x`。
- 同一对象在旁白和画面中使用同一符号，例如统一使用 `√d_k`，并在首次出现时说明“d_k 是键向量的维度”。
- 数学公式按旁白进度分段呈现；需要数学排版时使用 LaTeX（`MathTex`）及其依赖。
- 1080p 画面中的标签至少 28 px，内容保留在距画面边缘 5% 的安全区域内。
- 最终状态停留 2 至 3 秒，并在画面上保留核心结论。

## 构建

使用已有 Manim 环境时，可按以下方式组织：

- 用一个 `Scene` 类组织场景，每段对应分镜表的一行。从时长记录文件读取音频长度，用于 `run_time` 和 `wait`。
- 默认以 1080p 渲染（`manim -qh`），用户指定分辨率时按其要求。需要片头和回顾卡片时，可用 `manim -s` 渲染静帧，保持颜色与字体一致。
- 为本次产物生成实际使用的时长记录文件、场景代码和构建命令。普通文字使用支持中文的字体。

## 合成示例

下面假定本次任务已经生成 `visual-01.mp4` 与对应的 `scene-01.mp3`，各场景分辨率、帧率和音频规格相同。文件名替换成实际路径。先用 `ffprobe` 取得音频时长，再按时长安排动画。

```sh
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 scene-01.mp3
ffmpeg -n -i visual-01.mp4 -i scene-01.mp3 -map 0:v:0 -map 1:a:0 -vf "tpad=stop_mode=clone:stop=-1" -c:v libx264 -pix_fmt yuv420p -r 30 -c:a aac -ar 44100 -ac 2 -shortest scene-01.mp4
```

为每个场景重复合成，再按顺序创建 `segments.txt`。内容中的绝对路径须对应真实产物，例如：

```text
file '/absolute/path/to/scene-01.mp4'
file '/absolute/path/to/scene-02.mp4'
```

```sh
ffmpeg -n -f concat -safe 0 -i segments.txt -c copy -movflags +faststart explainer.mp4
ffprobe -v error -show_entries stream=codec_type,width,height -show_entries format=duration -of json explainer.mp4
```

## 验证与交付

观看并听取导出的 MP4，检查事实解释、图示可读性、发音、时间安排和场景衔接。

- 确认存在音轨。用户给了严格时长时按严格要求验收；非严格目标可参考时长偏差不超过 15%。
- 检查每个场景及实际存在的片头、回顾卡片，确认字幕不遮挡标签或卡片页脚。
- 抽帧覆盖场景及关键转场，以原尺寸检查文字可读性、边缘裁切、变形过程中的乱码，以及画面与分镜的一致性。可用 `ffmpeg -vf fps=0.5` 指定采样频率，实际运行时补齐输入和输出路径。
- 已安装 whisper.cpp 等本地转写工具时，可转写音频并与旁白稿对照。自动转写辅助核对内容，不能替代听感验证；当前工具无法听取音频时要明确说明。

先在聊天中给出解释的核心结论，再按宿主支持方式展示视频，附可编辑场景源文件、旁白稿、参考资料与重建命令。缺少渲染工具或凭据时，说明哪些产物已完成，并提供后续所需命令。单独的 MP3 或分镜仍是中间结果；没有旁白的视频标为无旁白版本。
