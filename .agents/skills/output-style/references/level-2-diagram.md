# 二级：图解

图中文字使用 [ai-writing-rules](../../write/ai-writing-rules/SKILL.md) 的文本表达规则。先确定读者要看到的关系，再选绘图工具。

## 选择图种

读者需要看清步骤顺序、交互对象、包含关系或状态变化时使用图解。如果只是把列表装进方框，直接用列表即可。

| 内容 | 图种 | 布局 |
| --- | --- | --- |
| 各方随时间交换消息，如 OAuth、TCP 握手、API 调用链 | 时序图 | 每方一条垂直生命线，时间向下，箭头编号 |
| 带决策的步骤，如部署流水线、支持请求分流 | 流程图 | 从上到下或从左到右，仅在真实决策处使用菱形 |
| 状态及触发变化的事件，如 TCP 连接、订单 | 状态图 | 状态用方框，事件标在箭头上，标明起点和终点 |
| 部分之间的包含关系，如系统、文档、团队 | 树形图或嵌套框 | 根节点置顶，同级对齐 |
| 数据在组件间流动，如请求经过 CDN、缓存和源站 | 数据流图或架构图 | 组件按层分列，箭头标明传递内容 |

## 图要说明什么

- 每张图说明一个主要观点，并用一句图注点明。HTML 使用 `<figure>` 和 `<figcaption>`；Mermaid 或独立图片使用邻近的简短图注。
- 画出机制：例如用请求经过缓存的路径解释缓存。箭头标明动作或关系，如“写入”“使缓存失效”“每 30 秒轮询”，避免把静态归属误画成数据流。
- 比较方案时，展示各方案增加或移除的连线与组件。
- 用形状、位置、纹理和颜色共同表达状态，避免仅靠颜色区分。

只画来源支持的组件、边界和连线，未确认关系标注为假设。

## 选择实现

- 简单静态流程、时序、层级或状态图，宿主能直接展示时优先 Mermaid。
- 需要精确布局、空间关系、直接标注数值或独立矢量文件时用 SVG。HTML 可作为承载与查看方式，不因此升级成三级。
- 用户要继续拖拽编辑时用 Excalidraw；有对应工具就使用，没有则生成可导入的 `.excalidraw` 文件，并检查导入后的结果。
- 有既有图或用户指定格式时延续它。图多大、用什么颜色和字体由内容、显示位置与用户要求决定。

## SVG 与小屏显示

- 设置 `viewBox` 和 `width="100%"`，不固定像素高度。独立图可按桌面面板的显示尺寸绘制，宽度约 900 至 1300 个单位，使 1 个单位约对应 1 px、13 单位文字约显示为 13 px；嵌入宿主时按实际可读性调整。
- 箭头使用一个 `<marker>`，内部路径设为 `fill="context-stroke"`，让箭头继承各自连线的颜色。`currentColor` 取 SVG 的文字颜色，可能导致蓝线配黑色箭头。
- 使用直线或正交折线，仅在曲线承载含义时使用曲线。
- 箭头标签写清传递内容或发生的动作，例如“发送 code_challenge”。字段、请求头和参数名保留原样，并使用等宽字体。
- 平行箭头之间、标签与邻近连线之间保留至少 24 个单位的间距；标签不压线、不相互重叠。
- 为 SVG 设置 `role="img"`，并用 `<title>` 说明图的内容。

宽时序图缩到 390 px 时，文字可能无法阅读。选择以下一种方式处理：

- 用 `<div class="table-wrap">` 包裹 SVG，在产物内为容器提供 `overflow-x: auto` 等样式，并为 SVG 设置如 760 px 的 `min-width`。让图在容器内横向滚动，页面本身不横向溢出，并用读者的语言提示“左右滚动查看所有参与方”。
- 为小屏绘制第二份纵向布局，通过媒体查询切换。

在图旁提供带编号的步骤列表，使小屏读者和屏幕阅读器用户也能理解内容。

## 验证与交付

在实际展示方式下看图，确认主要关系完整、箭头准确、文字和连线不相互遮挡，显示尺寸可读。文件型产物用现有渲染器或浏览器查看；聊天内 Mermaid 检查语法与关系，无法取得渲染预览时说明这一限制。

修复已发现的内容或阅读问题；这些问题解决后交付，不为凑迭代次数重复重画。图配上直接回答问题的短说明；用户需要编辑时一并交付源文件。保留一级答案即可说清的内容，别把每一句话都塞进图里。
