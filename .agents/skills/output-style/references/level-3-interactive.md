# 三级：交互解释

页面文字使用 [ai-writing-rules](../../write/ai-writing-rules/SKILL.md) 的文本表达规则。在生成前明确：读者操作什么、什么发生变化、这一变化回答哪个问题。只有切换颜色或展开无关信息的页面，没有增加解释价值。

## 页面工作流

以下完整 HTML 工作流用于独立页面。在聊天内展示时，若有 `visualize` 技能，使用其规定的片段、展示入口和资源限制；解释流程保持相同。

1. 找到读者的主要问题，选一个能具体展示机制的例子，区分事实、假设和未知项。
2. 创建完整的 HTML 页面。优先使用内嵌 CSS 和 JavaScript 的单文件；用户已有应用或需要独立资源时沿用其结构。
3. 在有助于理解的地方加入交互，例如改变输入、逐步揭示过程、比较情景或观察机制。显示发生了什么变化及其原因，避免装饰性控件。
4. 使用清晰的层级、易读的字体和简短说明。控件提供标签、键盘操作和可见焦点，支持窄屏和减少动态效果的偏好。
5. 打开页面，操作控件并检查窄屏视图，同时验证示例逻辑与外观。修复问题后交付 HTML 和简短的打开说明，交代未能测试的部分。

动画用于引导注意力，页面规模以讲清问题所需为限。仅在用户要求时发布页面。

## 交互方式

按理解障碍选择一种或少数几种，不要求全部出现。下面的 `data-*`、类名和函数是实现约定；实际采用的行为需在当前产物中实现，或使用现有宿主组件。

### 联动高亮

让共享 `data-ref` 的正文术语、节点、连线、卡片和按钮一起高亮。鼠标悬停在任一关联元素上，或正文术语、按钮获得焦点时，突出整组元素并弱化其他图形。正文术语设置 `tabindex="0"`，同一元素可关联多个标识，例如 `data-ref="hit miss"`。每张图关联 2 至 4 个关键术语即可。

### 分步演示与场景播放

每一步突出相关部分，配一句说明；加上播放按钮和可拖动的进度条，即可按场景播放。

初始视图展示完整画面，让读者先看到答案。每个场景说明一个观点，每一步都有可见变化。由读者主动开始播放，不自动播放；减少动态效果模式下仍保留播放操作。

可操控的网页演示属于三级，不能代替用户要求的视频文件或旁白。

### 前后对比

在同一坐标系中切换同一张图，让读者看清变化的位置。可用 `button[aria-pressed]` 切换 `figure[data-view]`，用 `.only-before` 和 `.only-after` 分组；新增内容使用 `--ok` 颜色的描边，移除内容使用 `--risk` 颜色的虚线。静态版本使用相同比例的两张并排图。

### 实时变化的图示

让控件重新计算图示，帮助读者观察参数影响。例如，缓存有效期（TTL）滑杆可同时改变命中率、表示流量分配的点、负载条和结论文字。策略切换可以展示：同一份数据采用错误规则后，为什么会得到看起来更好却不正确的数字。

- 使用 1 至 3 个控件，如 `input[type=range]`、`button[aria-pressed]`，每个控件都改变读者关心的结果。
- 由同一份设置状态驱动纯函数 `model(settings)`，统一生成图示、数值和解释，避免各处另存不一致的状态。
- 已掌握真实当前值时，以它作为默认值并在刻度上标明；否则明确标注示例参数。打印及禁用 JavaScript 时显示默认结果，不显示控件；控件由 JavaScript 插入，打印时隐藏。减少动态效果模式保留操作能力，仅取消过渡动画。
- 在图注或 `<details>` 中展示公式，将简化模型标为“示意模型”。
- 默认只建模要解释的概念，避免复制生产逻辑后产生偏差。用户明确要求复现真实算法时，以其规范或代码为依据，并交代模型简化了什么。

TTL 与命中率的关系必须由明确的工作负载假设和计算支持，不能仅让滑杆带动任意数值。

## 验证与交付

验证控件确实改变同一份模型状态，图、数值和解释随之保持一致。对所选机制检查默认情景及一个会改变结论的边界情景；分步演示检查前进、后退和重置；没有使用的交互无需检查。

在浏览器里检查实际控件、窄屏布局、文字大小和运行错误。图示或模拟的因果关系也要验证，页面能打开不足以证明解释正确。

交付方式随宿主：聊天内呈现可直接操作的可视化，独立页面给出文件与必要的打开说明。回答中点明读者可以改变什么、从结果看懂什么，避免再复制整页文字。无法完成验证时说明具体缺口。
