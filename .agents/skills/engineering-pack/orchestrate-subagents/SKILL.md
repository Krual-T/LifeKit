# 协作编排

主控对用户目标、权限、任务分工和最终交付负责。执行者自行调查并作出范围内的实现判断；主控提供必要信息，解决跨任务问题，核验成果。

## 1. 选择协作方式

子智能体也有自己的会话。按实际协作关系选择模式，只读取本次需要的操作说明：

| 模式 | 适用情形 | 操作说明 |
| --- | --- | --- |
| 子智能体 | 主控派生有界子任务，例如并行探查、分工实现或独立审阅，使用宿主的父子任务机制收集结果 | [子智能体编排](references/subagents.md) |
| 独立会话 | 用户要求新开对话、由已有对话实施，或由主控持续协调多个独立任务 | [独立会话带队](references/independent-sessions.md) |

用户指定协作方式时按其要求执行。自主委派以独立工作流、上下文隔离或独立核验的实际收益为依据；任务很小、高度耦合或协调成本更高时直接完成。工具能力以当前宿主的声明与返回为准。

## 2. 划清任务与责任

先明确每项工作要交付什么、由谁负责、依赖什么，以及怎样判断完成。有现成任务记录时在原处维护；简单任务在主控上下文中说明即可。

- 并行编辑按文件、组件或工作树划分所有权，告知执行者保留并适配其他任务的改动；范围重叠或存在先后依赖时重划分工或串行执行。
- 委派沿用用户已授权的范围。任务说明写清本次交付边界；需要额外授权的动作由主控向用户确认，已明确授权的常规工作继续推进。
- 独立审阅只提供原始材料、范围和验收目标，让审阅者自行判断。

## 3. 筛选委派信息

根据接收方已有上下文，只补充会改变其决策或执行的信息：目标、已定取舍、任务特有边界、必要来源、交付物与完成条件。

- 规范和需求已有权威记录时，给准确入口及所需章节。先确认接收方可访问；无法访问时摘出必要内容。用户刚作出、尚未落入文档或覆盖旧规范的决定要直接写明。
- 将可自行查询的仓库状态留给执行者实时确认。只有固定基线、复现故障或定位成果确实依赖时，才附提交号、命令或文件明细。
- 区分用户要求、已核实事实和主控建议。传入影响行动的调查结论；保留执行者选择实现路径和提出异议的空间。
- 把授权经过压缩成当前授权边界；把主控其他工作的介绍压缩成与本任务有关的责任边界。

初次编写委派、信息过长或准备追发要求时，对照[bad case 与好示例](references/delegation-examples.md)。精简后仍要保留会影响成果和权限的要求。

## 4. 跟进与纠偏

派出后继续推进不依赖子结果的工作。依所选模式查看进展，在阻塞、范围变化、依赖交接或可验收成果出现时介入。

- 补充指令前先看最新进展，只发送新增要求、具体缺口或改变的决定。
- 迟缓或输出不足时先定位阻塞，优先让原执行者从已有成果继续；确实无法恢复或职责需要调整时再替换。
- 需要主控决策时，核对已有成果与具体取舍。实现细节由执行者处理，跨任务冲突由主控协调，超出授权的问题交给用户。

## 5. 验收与收口

按完成条件读取实际成果：文档核对引用与原始依据，代码核对 diff、执行结果和受影响消费者。对遗漏提出具体修订；结果冲突时回到证据判断。

证据足够或新增委派不会改变决策时停止扩展。主控整合结论，向用户说明已交付、未完成及需要决策的事项；区分执行者自报完成与主控已验收，交代仍在进行的相关任务。
