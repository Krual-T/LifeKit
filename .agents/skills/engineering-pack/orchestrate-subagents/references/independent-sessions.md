# 独立会话带队

适用于用户让主控新开对话、把任务交给已有对话，或统筹多个独立会话。独立会话可以另有用户输入、已有成果和自己的工作现场；主控按当前授权协调分工。

## 接手与委派

1. **确认对象和可用工具。** 用户指定会话时先读该会话；需要找执行者时按项目和任务发现候选，再读相关内容。身份以工具返回的会话标识及必要宿主信息为准。
2. **读取已有进展。** 确认用户最新要求、正在做的事、成果位置和阻塞。已有对话适合接续时复用；用户明确要求新开或现有职责不适合时创建独立对话。
3. **只补必要信息。** 新会话得到最少而完整的任务说明；已有会话收到本次增量。依据发送工具契约确认消息会立即执行、引导当前轮次还是排队，按实际回执报告。

跨会话发送须有用户授权，例如本任务的“让该会话落实”“由你监督并提出修订”。读取权限本身不授予发送权限；已有授权内的委派和跟进正常推进。

可用入口随宿主变化。当前可能只有列表和读取能力，也可能有创建、发送、等待等工具。缺少所需操作时，完成可做的读取、分析和待发送内容，说明具体缺口；历史工具目录、底层协议或另一会话的能力不能替代当前可调用入口。

## 主控保留什么

在已有任务记录或主控上下文中维护足够恢复工作的信息：任务与执行会话的对应关系、成果位置、已确认状态，以及下一项跟进动作。只保存当前实际用到的字段；会话 ID 主要用于主控定位，执行者需要回信或引用时再提供。

用户在执行会话中的新要求可能改变原分工。跟进时读取这些变化，按最新授权调整；遇到无法调和的目标或范围冲突，由主控向用户核对，先保留已有成果。

## 跟进到验收

- **主控运行期间**：推进独立工作，在主线阶段完成、依赖交接、执行者报告阻塞或交付成果时查看进展；宿主提供等待机制时优先使用，避免高频重复读取。
- **补充要求之前**：读取最新进展，围绕具体缺口给出反馈。将已完成工作纳入判断，修订沿原会话与成果继续。
- **会话结束一轮时**：检查实际交付。`idle` 或轮次结束可能表示完成、阻塞、失败或等待输入；发送成功仅表示请求被受理，具体含义按回执核实。
- **监督至交付的任务**：持续推进或等待相关成果，验收后再完成任务。用户要求先返回或确有阻塞时，交代尚未完成的工作及下一步。跨轮次跟进依赖已核实的通知或唤起机制；需要用户再次唤起时明确说明，主控恢复后从最新进展接续。

实现、PR、合并和部署按本次实际授权分别验收。主控读取成果及证据后给出结论；“已委派”“执行者报告完成”“主控已验收”分别表述。
