# 子智能体编排

适用于主控通过宿主派生子任务、利用父子任务机制协调工作的情形。目标、权限和验收沿用主入口。

## 分派与上下文

- 优先复用仍掌握相关上下文的子智能体。按实际需要选择探查、实施或审阅角色，并划清编辑所有权。
- 定点任务提供必要材料即可；子任务确实依赖完整历史时才选择继承。独立审阅传入原始材料和验收范围。
- 并发数量由可独立推进的工作决定。依赖未满足的任务等前置成果就绪后再启动。

## 操作与恢复

Codex 的 `collaboration` 工具按当前声明使用：

| 动作 | 入口与注意事项 |
| --- | --- |
| 创建子任务 | `spawn_agent`；保存返回的 Agent 标识 |
| 给运行中的子任务补充信息 | `send_message`；当前契约下不会唤起闲置 Agent |
| 让原 Agent 接续工作 | `followup_task`；可向闲置 Agent 分配后续任务 |
| 查看或等待进展 | `list_agents`、`wait_agent`；收到通知后读取消息与成果 |
| 停止错误方向的执行 | `interrupt_agent`；先确认目标及需要保留的现场 |

其他宿主使用其实际提供的对应能力。已有子任务结束一轮后，依据交付物判断是否完成；仍有缺口就向原 Agent 发后续任务。子智能体的标识和操作入口用于父子任务关系，独立对话使用会话模式。
