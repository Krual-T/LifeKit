# AI Writing Rules

围绕目标文本直接组织事实、判断、动作和边界。每项规则描述期望产物；编辑时依据源材料重建完整语义单元。

## 选择模式

| 模式 | 使用场景 | 产物 |
|---|---|---|
| `draft/prevent` | 新写、扩写、重构；被领域写作 Skill 调用 | brief、提纲和正文 |
| `detect` | 审计、标注、诊断 | P0/P1/P2 质量缺口报告 |
| `edit` | 润色、改写、去 AI 味 | 重写稿、变更说明、复核结果 |

创建文档默认使用 `draft/prevent`，从 brief 和提纲阶段建立质量目标。

## 写作契约

写作或审阅前确定：

- 文档类型、目标读者及其决策任务；
- 核心信息、语气、篇幅和格式；
- 必须保留的事实、术语、引文、代码、结构与作者表达；
- 证据来源、证据强度、分析判断和未知项；
- 适用的领域 profile 与结构主 Skill。

上下文足以支持时直接推断；其余信息作为显式假设或待确认项。领域规则优先于通用风格偏好。

用户未指定修改幅度时，采用最小充分改写：只处理有证据的质量缺口，保留有效结构和个性表达。短句与低风险文本在内部完成检查，不外显 brief、模式选择和审计过程。

按任务读取：

- 选择领域与声线时读取 [context-profiles.md](references/context-profiles.md)；
- 执行逐项审计时读取 [pattern-catalog.md](references/pattern-catalog.md)；
- 写评论、博客、研究综合、复盘等判断性文本时读取 [argument-quality.md](references/argument-quality.md)；
- 写 PR、工作成果或复盘中的变化与效果时，读取 [change-narratives.md](references/change-narratives.md)，按职责组织主题，连接具体变化、关键机制与直接效果；
- 使用检测与编辑输出格式时读取 [audit-and-edit-contracts.md](references/audit-and-edit-contracts.md)；
- 修改规则或验证行为时读取 [evaluation-cases.md](references/evaluation-cases.md)。

## 质量目标

1. **事实完整**：每个事实、数字、引文、案例、状态和因果关系都能回到输入材料或明确来源。
2. **语义忠实**：原意、证据强度、责任主体、适用条件、例外和不确定性保持稳定。
3. **直接陈述**：定义说明对象是什么；功能说明主体做什么；结论说明依据、判断和适用边界。
4. **信息推进**：每段增加事实、区分、因果、约束、选择、后果或可执行动作。
5. **具体可核验**：评价连接机制、证据、状态或验收条件；抽象概念落实到主体、动作和对象。
6. **术语稳定**：引文、代码、命令、路径、标识符、法规用语和领域术语保持原样或遵循领域规范。
7. **声线连续**：句长、直白程度、术语密度、第一人称和惯用节奏延续作者已有表达。

## 肯定性表述

规则、正文和修改建议优先写目标状态、责任主体、动作、范围与验收条件。

- 定义句直接给出类别、职责或机制。
- 范围句直接说明适用对象、阶段、责任人和交付物。
- 约束句直接说明允许的动作、触发条件和处理方式。
- 评价句直接连接事实、数据、机制或明确判断。
- 修改建议给出完整目标句，替换原有语义单元。
- 双重否定一律重写为肯定性目标句；规则本身也遵循这一标准。

否定表达在自身承载真实语义时使用，包括范围排除、法律义务、证据限制、概念辨析、纠正已出现的误解和回应已提出的观点。其余场景直接陈述目标事实。

示例：

`这不是一个报表工具，而是一个决策平台。`

目标表达：`该平台汇总业务数据，支持方案比较并记录决策。`

## 根因编辑

把问题定位到事实模型、论证结构、责任边界、抽象层级或声线。根因修复采用覆盖式重写：用正确目标逻辑替换完整语义单元。局部补充只处理独立的错字、标点和格式问题。

1. 从原文和证据中提取目标命题；
2. 明确主体、动作、对象、依据、条件和状态；
3. 直接重写整句、整段或对应结构；
4. 用目标版本覆盖旧逻辑；删除或替换 Prompt、指令文件中的要求时，一并删除对应旧指令及仅解释其失效的过渡说明，有回顾价值的变更原因进入提交说明或变更记录；
5. 复核事实、语义、声线与上下文衔接；按首次读取的视角通读修改段落及直接引用，确认保留的规则表达当前有效的目标、动作和边界。

附加免责声明、反向补充、词语替换和例外堆叠只在其本身承载必要信息时进入成稿。

## `draft/prevent` 工作流

1. **锁定 brief**：明确读者、目的、事实边界、领域 profile 和 must-keep 内容。
2. **建立命题结构**：每节回答一个真实问题或支持一项决策，标出事实、判断、动作和未知项。
3. **逐段成文**：先写核心命题，再补证据、机制、条件和后果；每段保持明确主体和信息推进。
4. **局部复核**：按质量目标检查已完成单元，直接重写偏离目标的完整语义单元。
5. **全文复核**：检查术语、节奏、论证推进、证据强度和章节衔接。

## `detect` 工作流

1. 识别文档类型、作者声线、证据范围和 must-keep 内容。
2. 按 P0、P1、P2 收集有原文证据的质量缺口，同一根因合并报告。
3. 说明位置、原文、目标、实际影响、语境和目标表达方向。
4. 保持正文原样。

## `edit` 工作流

1. 记录 3-5 个声线信号。
2. 完成 detect，按 P0、P1、P2 排序。
3. 根据证据重建受影响的完整语义单元，优先处理根因。
4. 保持原有事实顺序和责任边界；结构调整由真实论证需要驱动。
5. 对成稿执行第二遍审计。

## 与其他 Skill 组合

- 技术、产品、学术、法律等文档由当前任务实际可用的领域 Skill 主导结构、专业判断和验证，本 Skill 控制跨领域写作质量。
- 同一文档指定一个结构主 Skill；未提供领域 Skill 时，根据文档类型和用户目标直接选择结构。
- 现有文本的质量审计使用本 Skill 的 `detect`；改写请求使用 `edit`；新写和扩写使用 `draft/prevent`。
- 套话、填充词、机械排比和节奏等表层模式作为 P1/P2 线索处理；词句级调整不得覆盖事实完整、语义忠实、领域规范和作者声线要求。

## 完成标准

- 关键陈述具备明确主体、对象、依据和适用条件；
- 普通定义、功能、总结与价值说明采用直接陈述；
- 规则与边界以责任主体、目标动作、适用范围和验收条件表达；
- 每段对问题形成可指出的信息推进；
- 判断呈现证据、分歧、选择理由与真实不确定性；
- 术语、事实、引文、代码、作者声线和领域惯例保持稳定；
- `edit` 模式已完成第二遍审计。
