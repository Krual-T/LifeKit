# Evaluation Cases

修改规则、profile 或输出契约后，逐例运行 `detect`；对 edit 案例运行目标状态重写。验证质量判断、语义保持和重写范围。

## 核心案例

| 场景 | 输入 | 预期目标 |
|---|---|---|
| 技术定义 | `这不是一个普通的任务模块，而是驱动业务闭环的智能中枢。` | P1；改写为有材料依据的具体职责 |
| 产品状态 | `平台已经显著提高用户效率。`，材料只说明功能计划 | P0；分别陈述计划功能和待验证结果 |
| Wiki 综合 | `两种方案各有优势，需要在效率与质量之间取得平衡。` | P1；补充比较标准、证据、结论或未知项 |
| 学术论文 | `The method significantly outperforms prior work.`，材料缺少统计量和表格指针 | P0/P1；连接已有证据并校准动词强度 |
| 项目申请 | `团队已验证该路线可规模化部署。`，材料只有实施计划 | P0；陈述拟验证内容和已有可行性依据 |
| 评论文章 | 三段分别换词表达“AI 影响很大” | P1；合成为包含证据、机制或作者判断的论证单元 |
| 外发材料 | `业内普遍认为本产品处于领先地位。` | P1；连接真实来源、差异化机制或明确内部判断 |
| 对话残留 | `希望这对你有帮助，如需扩展请告诉我。` | P0；交付正文只保留文档内容 |

## 语境保护

| 场景 | 输入 | 预期目标 |
|---|---|---|
| 技术规格 | `本阶段不迁移历史附件，只迁移结构化记录。` | 保留；否定定义真实范围 |
| API 文档 | 多次重复 `request_id` | 保留；重复维护稳定标识符 |
| 学术论文 | `The association may reflect residual confounding.` | 保留；谨慎语气匹配证据限制 |
| 法律条款 | `未经书面许可，不得向第三方披露。` | 保留；规范性否定表达法律义务 |
| 验收标准 | 三项并列且分别可验证 | 保留；结构服务完整验收 |
| Wiki 笔记 | 短句、候选列表和未决问题混合 | 保留；工作性结构符合语境 |
| 评论文章 | 作者引用已存在的反方观点后回应 | 保留；对照承担真实论证功能 |
| 研究综合 | 两个来源冲突，正文说明暂缓裁决所需证据 | 保留；不确定性具有证据依据 |

## PR 与工作复盘

按 [change-narratives.md](change-narratives.md) 审阅或重写，验证主题组织和信息完整性。

| 场景 | 输入与依据 | 预期目标 |
| --- | --- | --- |
| 配套机制遗漏 | “支持后台导出”；材料包含任务持久化、状态查询、排队取消和失败重试 | P1；在同一导出主题内保留关键机制与任务管理能力，分点表达 |
| 行为范围夸大 | “用户随时可以中断导出”；材料仅支持取消尚未开始的任务 | P0；恢复准确范围，并说明执行中任务继续处理 |
| 重构基线错误 | “新建执行器与业务模块分层”；基线已有分层，本次移交报表字段和格式规则 | P0；说明职责转移、调用变化与格式规则独立维护的效果 |
| 效果空泛 | “优化导出体验”；材料包含进度展示、结果查询及重新进入任务页 | P1；连接具体操作与用户判断进度、稍后取回结果的能力 |
| 独立主题遗漏 | PR 包含导出、权限和运行指标，正文只写最近的导出提交 | P1；对照完整差异补齐独立主题，各自保留目的、变化与效果 |
| 简单修复 | “修复导出文件名中的空格导致下载失败，保留原始文件名。” | 保留；无需扩成架构主题和多层列表 |
| 个人复盘 | “今天散步时心情放松了一些，想继续保持。”，来自本人陈述 | 保留；无需改为产出、指标或项目成果 |

## 事实完整回归

输入：

> 新版本提供了更强大的能力，能够显著改善团队效率。

合格输出依据已有材料陈述具体功能、明确评价的证据状态，或将效果标为待验证。数字、机构、用户反馈、案例和个人经历均须来自输入。

## 声线回归

给定带有稳定第一人称、克制幽默或长句推演的原文，合格输出满足：

- 修改集中在有证据的质量缺口；
- 原有句长分布、直白程度和专业密度保持连续；
- 具体细节来自材料；
- 冒号、破折号、被动语态和重复术语按语境功能处理。

## 根因重写回归

输入：

> 你的产出是建议，不是裁决。不要评级，不要给通过结论，也不要设置交付门禁。你需要关注事实与表达。

合格目标表达：

> 你的产出包括事实核对结果和具体修改建议。项目负责人作出最终验收结论。

该案例验证四点：完整语义单元重写、责任主体明确、目标动作直接陈述、历史纠偏清单退出成稿。

## Prompt 规则替换

背景：同步工作已交给 Hook，原来的手动执行要求已撤销。

输入：

> Hook 在编辑后同步索引。无需再手动运行旧同步命令。

合格目标表达：

> Hook 在编辑后同步索引。

若自动同步失败时仍需手动恢复，保留这项当前有效的条件与动作。该案例验证旧流程的退役说明退出指令正文，同时保留仍有执行意义的异常处理。

## Draft 回归

对同一 brief 分别检查提纲和成稿：

1. 每节回答真实问题或支持具体决策；
2. 事实、分析判断、计划和结果状态清晰分层；
3. 判断性文本呈现证据分歧、选择理由和未知项；
4. 定义、功能、边界和约束采用目标结构；
5. 个人经验和具体细节具有输入依据。

## 通过标准

- 核心案例获得准确优先级、根因和目标表达；
- 语境保护案例保持原有领域功能；
- edit 保持事实、语义范围和作者声线；
- draft 从 brief 和提纲阶段建立质量目标；
- `SKILL.md`、`agents/openai.yaml` 与 references 的名称、链接和行为约定保持一致。
